Enhancement 3

Database Enhancement

Evolving a basic SQLite implementation into a normalized relational design that preserves data, enforces integrity, and supports meaningful operational queries.

Home / Database Enhancement

Artifact description

The artifact selected for this enhancement is my Inventory Management Android application, originally created during CS 360: Mobile Architecture and Programming. The application allows users to create an account, securely log in, and manage inventory by adding, viewing, updating, and deleting items. Each item stores a name, SKU, quantity, and low-stock threshold. Throughout CS 499, I used this application as the single ePortfolio artifact because it provided opportunities to demonstrate growth in software engineering, algorithms and data structures, and database design through meaningful enhancements.

For the database enhancement, I expanded the application's SQLite database to better reflect a real-world inventory management system. The work focused on improving the schema, preserving existing data during upgrades, strengthening integrity, and implementing relationships between multiple tables.

Justification for inclusion

I selected this artifact because it demonstrates a broad range of computer science skills while showing my ability to improve an existing software project rather than create a replacement. The original application contained a single inventory table with basic CRUD functionality. Although functional, the design did not demonstrate relationships, normalization, indexes, joins, constraints, or safe migration.

I redesigned the database by separating categories into their own table and connecting inventory records to categories through foreign keys. I also implemented indexes for frequently queried fields, SQL JOIN queries that return category names with inventory records, and a migration process that preserves existing users and inventory instead of deleting them. Additional improvements expanded category CRUD, enabled category assignment when creating items, displayed category information on inventory cards, and added category filtering.

Database design and improvement

  • Normalization: category names are stored once in a dedicated table, reducing repeated data and supporting consistent updates.
  • Referential integrity: each inventory record stores a category foreign key. ON DELETE RESTRICT prevents removal of a category still in use.
  • Constraints: CHECK constraints prevent negative quantities and low-stock thresholds.
  • Indexes: SKU and category identifiers are indexed because the application frequently searches or filters by these values.
  • JOIN query: inventory records and their category names are retrieved together in one relational query.
  • Safe migration: version-two records are copied into the normalized version-three schema and assigned to “Uncategorized,” preserving user accounts and inventory.
  • Expanded CRUD: repository and database operations support creating, reading, updating, and deleting categories while inventory items retain their assignments.
Data-preservation improvement: the original upgrade method dropped both tables and erased saved information. The enhanced transaction-based migration creates the new schema, copies records, recreates indexes, and commits only after the full operation succeeds.

Course outcome alignment

The primary outcome demonstrated is the ability to use well-founded computing techniques, skills, and tools to implement solutions that deliver value and accomplish industry-specific goals. Normalization, constraints, indexes, JOIN queries, repository-backed CRUD operations, and migration collectively make the application more realistic, maintainable, and useful.

The enhancement also supports the security outcome. Foreign keys and CHECK constraints protect data integrity; parameterized query operations reduce unsafe input handling; preserved password hashes and salts remain intact through migration; and background repository access limits persistence responsibilities to a defined layer. Professional communication is demonstrated through schema documentation, clear interface labels, and this narrative's explanation of design trade-offs.

Reflection on the enhancement process

Enhancing the database provided valuable experience with relational design and demonstrated the importance of planning architecture beyond an initial implementation. One of the most significant lessons was the value of normalization. Separating categories reduced redundant data and made future expansion easier. Inventory items now reference categories through a foreign key instead of repeating names in every record.

Another important lesson involved migration. The original application recreated the database whenever its schema changed, causing user data to be lost. Implementing a migration that preserves users and inventory taught me how carefully production data must be handled. Existing items were moved into the new table within a transaction and assigned to a valid default category, allowing the app to upgrade without requiring users to start over.

I also gained experience writing JOIN queries and creating indexes. The JOIN retrieves inventory items with category names in a single operation, while indexes support frequently used searches and filters. One challenge was updating the existing application without breaking earlier repository, algorithm, and UI work. Each schema change affected models, repository methods, add-item behavior, item cards, and filters. Testing after each checkpoint helped verify that data continued to save across restarts and that older records survived the upgrade.

No specific instructor feedback required changes to the original plan. The final implementation met the planned database outcome while replacing the initially considered Room migration with a more direct demonstration of relational design, integrity, and schema evolution.

Conclusion

This enhancement transformed the original inventory database into a more robust and scalable system. By normalizing category data, preserving records during upgrades, enforcing relational integrity, and improving query support, I demonstrated meaningful growth in database development. Combined with the earlier software and algorithm enhancements, the artifact represents my readiness to maintain and improve data-dependent systems in an IT Administrator role.
