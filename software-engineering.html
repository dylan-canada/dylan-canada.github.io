Software Design & Engineering

Refactoring a functional mobile application into a more modular, maintainable, testable, and resilient system.

Home / Software Design & Engineering

Artifact description

The artifact is an Inventory Management Android application originally created in CS 360: Mobile Architecture and Programming. It was built with Android Studio and Java and allows users to create accounts, sign in, store inventory records, update quantities, delete items, and receive low-stock SMS alerts. I selected it because its complete workflow provided a strong baseline for demonstrating growth beyond basic functional requirements.

Why this artifact belongs in my ePortfolio

The original application worked, but several activities communicated directly with the SQLite helper and combined user-interface behavior with persistence logic. That coupling made the application harder to test, maintain, and extend. Enhancing this artifact allowed me to show that software engineering is not only about adding features; it is also about improving the structure that supports reliable future change.

Enhancement and skills demonstrated

I introduced repository classes between the activities and the database helper. Database work now runs through a shared executor instead of blocking the Android user-interface thread, and callbacks return results to the main thread where views can be updated safely. This change improved responsiveness while separating persistence concerns from presentation concerns.

I also centralized reusable validation, improved error handling, organized activity initialization into focused methods, and replaced a hardcoded SMS destination with configurable alert settings. The enhanced design reduces duplicated logic and makes the code easier to reason about. The application can now grow without forcing each activity to understand low-level database operations.

Key engineering decision: retain the existing Java/SQLite foundation while introducing a repository and executor layer. This delivered meaningful architectural improvement without a risky full rewrite.

Course outcome alignment

  • Professional communication: clearer documentation, naming, and code organization help technical readers understand the system.
  • Computing practices: repository-based architecture, asynchronous persistence, validation, and modular design apply established software-engineering techniques to deliver value.
  • Security mindset: input validation, password hashing already present in the artifact, configurable permissions-based alerts, and safer error handling reduce preventable weaknesses.
  • Collaboration: separation of concerns and documented interfaces make future work easier to review, divide, and maintain in a team environment.

Reflection

The enhancement taught me to evaluate software quality beyond visible functionality. Moving persistence logic out of the activities required tracing how data traveled through the application and defining clean boundaries between layers. I learned that architectural changes should be introduced incrementally and tested after each step so working features remain stable.

A primary challenge was protecting the original behavior while changing how the application performed database work. Using compatible repository methods and callbacks allowed the user interface to remain familiar while the internal structure improved. Troubleshooting the add-item flow also reinforced the importance of testing persistent state and existing database versions, not only fresh installations.

No specific instructor feedback required a change to the planned outcome coverage. The finished enhancement follows the approved direction and provides stronger evidence of maintainability, responsive execution, communication, and security-conscious design.
